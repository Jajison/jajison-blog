# 做一个每周都能复用的工作汇总工具

**先修**：[04–08 课](../learn/04-workspace.md)。**需要**：Python 3.10+、练习包。**交付**：一份自动生成的 Markdown 报告与验证记录。预计 40 分钟。

## 从小样本开始

[下载练习包](../downloads/ai-workshop.zip)，解压并在 ai-workshop 根目录打开终端。input/records.json 包含四条记录：

| 编号 | 任务 | 状态 | 分钟 |
| --- | --- | --- | --- |
| W01 | 页面初稿 | done | 45 |
| W02 | 确认场地 | pending | 30 |
| W03 | 报名表 | done | 20 |
| W04 | 整理反馈 | done | 25 |

先手算：总计 120 分钟，已完成 90 分钟，待办 30 分钟。这些数字是验收依据。

## 跑通一遍

~~~sh
python3 report.py
python3 report.py --output output/report.md
~~~

Windows 将 python3 换为 py -3。第一条只预览，第二条生成新文件。输出应列出四条任务，不能只给一个无法追溯的总数。

再次保存到同一文件时，程序应拒绝覆盖。换一个输出名，或用文件管理器处理自己确认不再需要的测试结果。

## 让 AI 加一项小功能

可以选择“显示待办耗时”或“按状态分组”，一次只选一个。要求保持输入校验、默认预览和拒绝覆盖行为，并验证原有四条数据。

为了避免覆盖配套成品，可先复制 report.py 为 report-practice.py，再让 AI 改副本。

## 至少测试四种输入

1. 正常四条记录：数值应与手算一致。
2. 空列表 []：计数与总分钟都为 0。
3. 重复编号：明确报错，避免重复计数。
4. minutes 写成“45分钟”：明确报错，不静默当成 0。

再检查一项文件行为：已存在的输出不应被改写，输入文件内容不应变化。

这些测试不是要你精通测试框架，而是让“AI 写的脚本”变成“你知道适用条件的小工具”。

## 进阶：同一份数据，换成 SQL 与 HTTP

先保证上述脚本结果正确，再运行练习包中的 SQLite 演示：

~~~sh
python3 sqlite_lab.py --status done
python3 sqlite_lab.py --database output/workshop.db
~~~

第一条使用内存数据库，筛选已完成记录，应为三条、90 分钟；进程结束后内存库消失。第二条把四条输入写入一个新 SQLite 数据库文件，方便查看持久化结构；再次使用同一目标时拒绝覆盖。这个脚本用于创建演示库，不是打开和修改已有数据库的通用工具。

比较 JSON 脚本与 SQL 查询的结果，理解字段约束、参数化查询和事务分别保护什么。完整解释在 [数据与 SQL](../guides/data-and-sql.md)。想把同一统计提供给其他程序，继续 [网页与 API](../learn/09-web-and-api.md)的双终端 GET/POST 实验。

三种实现共享同一数据口径，不应该因为换了存储或传输方式就改变“已完成耗时”。这种跨实现核对可以发现字段遗漏与筛选错误。

## 写下交接说明

在自己的 README 里记下：输入字段和允许值；运行命令；结果位置；已测试的情况；当前限制。示例只处理 JSON 格式、非负整数分钟，状态只接受 done / pending。

以后要接 CSV 或 Excel，再单独新增读取步骤，保留相同计算与验收口径，不需要立刻更换整个系统。
