# LLM：它会很多，为什么仍会说错

**这一课做成什么**：能判断该补资料、换工具，还是更换模型。

**LLM** 是大语言模型。它从大量数据中学习语言与其他模式，能够完成写作、抽取、代码生成等任务。聊天产品通常在模型之外，还提供历史管理、文件处理、搜索和工具执行。

同一个模型接上不同工具，表现可能很不同。不要把“这个产品能上网”直接当成“模型本身存着最新网页”。

## 训练与使用是两件事

| 阶段 | 白话解释 | 是否通常改变模型权重 |
| --- | --- | --- |
| 预训练 | 从大规模数据学习基础模式 | 是 |
| 后训练 | 用示例、偏好或奖励改进任务表现 | 是 |
| 推理 | 使用已有模型处理当前输入 | 通常不是 |

SFT 是监督微调，用示例教模型怎样响应；RL 是强化学习，通过奖励反馈优化行为。这里只需要知道它们属于训练方法，不必先学习优化公式。

上传一份文件让模型回答，通常属于给推理提供上下文，不等于你训练了一个新模型。产品是否把数据另用于训练，是服务设置与数据政策问题，要单独确认。

## 流畅为什么不等于正确

模型生成的是条件概率意义上合适的后续内容，可能误解资料、补出不存在的细节或使用过时知识。**幻觉**通常指这种看似可信却不受事实支持的输出。

低 temperature 常使输出更集中，高 temperature 常使采样更多样；它不是“事实准确度旋钮”，低温也会稳定地回答错误答案，而且并非每个模型都开放相同参数。

## 遇到问题，先选对动作

| 现象 | 优先尝试 |
| --- | --- |
| 不知道内部规定 | 提供适当资料或增加检索 |
| 把金额加错 | 使用计算器或确定性脚本 |
| 输出结构不一致 | 给结构示例，并做格式校验 |
| 多步逻辑仍频繁失败 | 缩小任务，比较更适合的模型 |
| 查询最新状态 | 使用能访问当前信息的工具，并检查来源 |

不是每个失败都靠换更大的模型解决。更强的模型也可能更慢、更贵，而更简单的任务可能不需要它。

## 一个够用的选型方法

准备五到十个真实代表问题，分别看正确率、速度、成本和工具兼容性。在相同条件下比较，不只看一段最惊艳的回答。保留当时的模型标识与日期，避免把一次测试结论永久化。

**动手做**：给 AI 一个它无法从材料知道的问题，如“下个月活动预算最终是多少”。合格行为是说明缺信息或请求资料，而不是为了完成任务编一个数字。

**完成标准**：能区分知识不足、计算错误、格式问题和多步决策问题，并选择对应的改进方式。
