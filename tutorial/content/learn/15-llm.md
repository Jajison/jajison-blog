# LLM：从训练目标到生成、推理与幻觉

**这一课做成什么**：区分模型、产品和运行系统；从训练目标理解能力来源，而不是把 AI 当成会检索一切的数据库。

## LLM、聊天产品、Agent 是三层

LLM 是大语言模型，规模没有统一的单一参数门槛。许多常见生成模型以 Transformer 为基础，但语言建模并不在定义上只允许一种架构。

聊天产品在模型外提供界面、历史、文件解析、搜索、账户和计费。Agent 系统进一步提供工具执行、状态、权限和控制循环。因此同一模型在两个产品里表现不同，不必然是模型权重不同，可能是上下文和工具配置不同。

## 预训练在优化什么

常见自回归语言模型把序列概率分解为：

$$
p_\theta(x_1,\ldots,x_T)=\prod_{t=1}^{T}p_\theta(x_t\mid x_{<t})
$$

$\theta$ 是模型参数，$x_{<t}$ 是当前位置之前的 token，$\prod$ 表示连乘。训练通常最小化负对数似然，常按有效 token 数归一化：

$$
L=-\frac1T\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t})
$$

比如序列“我 / 喜欢 / 阅读”，训练会提供“我”去预测“喜欢”，提供“我 喜欢”去预测“阅读”。实际 tokenizer 切分不一定与斜线一致。训练目标来自文本本身，因此属于自监督，不需要人为给每个 token 单独标注。

“预测下一 token”是目标形式，不等于模型只能做简单词频统计。为降低大量复杂序列上的损失，网络可以学习丰富的语言、知识和推理相关表示；但这种目标本身不是事实验证器。

## 从基础模型到可用助手

| 阶段 | 典型数据与信号 | 改变什么 | 常见风险 |
| --- | --- | --- | --- |
| 预训练 | 大规模文本、代码等；语言建模损失 | 基础参数与通用表示 | 低质数据、重复、污染 |
| 继续预训练 / mid-training | 领域、长文本、数学等定向数据 | 参数与目标能力分布 | 遗忘、分布偏移 |
| SFT | 指令、回答、工具轨迹等示范 | 指令响应行为 | 模仿错误、覆盖不足 |
| 偏好优化 / RL | 偏好对、奖励、可验证反馈 | 响应或行动策略 | 奖励漏洞、过优化 |
| 推理 | 当前提示、资料、工具结果 | 通常只改变本次运行状态 | 上下文不足、幻觉、失败传播 |

这些阶段可组合、交替，并非所有模型都有完全相同的流水线。SFT、DPO、PPO、GRPO 的区别与公式见 [训练与对齐](../guides/training-and-alignment.md)。上传文件作为上下文通常不是微调；服务是否另用数据训练需看其政策，不能从模型计算过程反推出隐私承诺。

## 生成不是把最高分句子整段取出来

每一步先得到词表 logits，再按解码策略选 token。贪心选最高分；采样按概率抽取；top-k 限制候选数量；top-p 取累计概率达到阈值的候选集合；温度调节分布集中度。它们的具体支持与组合以模型接口为准。

低温通常更稳定，但稳定地犯错仍然是错。固定 seed 也不必然跨硬件、并行方式、服务版本得到完全相同输出。实验比较应记录版本和参数，必要时多次运行。

模型选出的 token 追加到上下文后，后续生成又受它影响。前面编出的错误前提可能被继续展开成一段自洽故事，这也是逐项核对出处的重要原因。

## 上下文、KV Cache、长期记忆

上下文窗口是一次处理可容纳的 token 范围，通常涉及系统指令、用户输入、工具返回及生成预算；不同服务如何计算有具体规则。标称最大窗口不是所有位置都同样有效的保证。

KV Cache 保存当前推理中可复用的键值表示，帮助避免重复计算，不是永久知识库。产品“记忆”通常涉及数据库或提示拼接，也不等于模型参数实时更新。详见 [推理与部署](../guides/inference-and-deployment.md)。

## 推理有两个含义

工程里的 inference 指执行已训练模型，所有生成都属于它；reasoning 指解决需要逻辑推演的任务。所谓推理模型通常针对后者做专门训练或采用更多测试时计算。输出更长的思考文字不自动证明逻辑正确；应检查最终答案、可验证中间结果和实际工具证据。

增加测试时计算可能包括生成更多候选、搜索、验证或迭代，带来质量、延迟、费用之间的权衡。不是所有任务都值得无限“多想一会儿”。

## 幻觉从哪里来，怎么处理

幻觉可表现为不存在的事实、错误归因、编造引用或不受给定材料支持的回答。成因涉及训练数据、知识时效、概率生成、任务歧义、上下文读取失败和评估激励，不能归结为一个 temperature 参数。

| 失败 | 优先动作 | 为什么 |
| --- | --- | --- |
| 不知道内部规定 | 提供材料或 RAG | 模型未必拥有这份知识 |
| 精确计算出错 | 确定性程序与单元测试 | 计算结果可直接验证 |
| JSON 格式不稳定 | 结构化约束加 schema 校验 | 格式要求可程序检查 |
| 最新状态不明 | 查询当前来源并看时间 | 参数知识可能过期 |
| 多步行动走偏 | 分解任务、工具约束、停止条件 | 运行控制比口头承诺可靠 |
| 资料仍无法支持答案 | 明确拒答或追问 | 换更大模型不能创造不存在的依据 |

## 动手做

用同一段公开文字设计三种任务：提取日期、生成摘要、询问原文没写的预算。为每种先写验收标准，再比较两次输出。标记格式失败、事实失败和拒答是否合理，不要只挑最漂亮的一条。

**完成标准**：能解释训练更新权重与推理利用上下文的区别，知道采样参数的作用，能为至少三种错误选择不同修复方式。

<details>
<summary>自测：模型在一个基准上分数更高，是否就一定更适合你的应用？</summary>

不一定。任务分布、语言、提示、工具、延迟和预算都可能不同。基准提供参考，真正的选型应依赖代表任务上的可复现实验，还要检查数据泄漏与评分方法。
