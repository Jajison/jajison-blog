# 和 AI 开发：先做一个只有三件事的小网页

**这一课做成什么**：做出并运行一个个人待办网页。

“做一个完整效率平台”很难验收。把目标缩成“新增待办、标记完成、导出清单”，就能很快知道第一版是否有效。

这就是**最小可用版本**：范围小，但从输入到结果完整走通。

## 给 AI 一张产品任务卡

~~~text
帮我做一个个人待办网页。我不懂代码，请先解释文件放在哪里、怎么运行。

第一版只做：新增文字待办、勾选完成、导出为 JSON。
界面：中文，简洁，手机上也能用。
保存：当前浏览器 localStorage；页面说明“仅此浏览器保存”。
技术：一个独立的 todo.html，包含 HTML、CSS、JavaScript；无外部依赖。
约束：无登录、无远程请求、无 API 密钥；空文字不能新增。
验收：新增三条，完成一条，刷新后仍保留；导出含三条及各自状态。
先实现这一个页面。完成后列出实测结果和未验证项。
~~~

如果使用能改文件的 AI 编程工具，在独立练习目录里让它工作。如果只有聊天工具，让它输出完整 todo.html，保存为纯文本文件；确认扩展名不是 .html.txt。

## 用配套成品先理解交付物

练习包里也提供 todo.html，可以先阅读或运行作为对照。它不需要安装网页框架。

在 ai-workshop 根目录启动本地预览：

~~~sh
python3 -m http.server 8000 --bind 127.0.0.1
~~~

Windows 将 python3 换为 py -3。在浏览器打开 http://127.0.0.1:8000/todo.html 。保持终端运行，用完后回到终端按 Ctrl+C 停止。

绑定 127.0.0.1 让这个练习服务器只在本机访问。若 8000 被占用，改成 8001，并同步修改网址。不同端口属于不同站点来源，本地待办也会分别保存。

## 功能一项一项加

先验收新增与勾选，再验收保存与导出。后面想加“筛选未完成”，就只提这个需求，并要求原有四项检查仍通过。

这是与 AI 合作的基本节奏：描述一个变化 → 查看改动 → 运行 → 对照预期 → 保存版本。让 AI 自己说“已完成”只是反馈之一，最终仍看实际页面和文件。

## 动手做

输入三条虚构任务，勾选第二条，刷新页面，再导出 JSON。打开导出文件，确认有三条记录，只有第二条 completed 为 true。

清理浏览器站点数据、使用隐私窗口或换设备，都可能使本地记录不可用。导出文件是这个练习的可携带结果，第一版还没有导入和云同步。

**完成标准**：能从空页面完成整套流程，并清楚知道数据保存在何处。

<details>
<summary>自测：为什么第一版没有账号和多端同步？</summary>

它们增加身份、存储与网络问题，却不是验证“这个待办工具有用”所必需。先验证用途，再决定是否值得增加复杂度。
