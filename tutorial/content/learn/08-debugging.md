# 报错不是失败：把问题缩小到能修的一步

**这一课做成什么**：能提供可复现的问题描述，并验证修复。

一个脚本不能运行，可能是目录错了、数据格式错了，也可能真是代码有问题。先区分是哪一种，比连续说“还是不行”有效。

## 给 AI 一份能复现的现场

~~~text
系统与终端：Windows 11，PowerShell。
运行位置：解压后的 ai-workshop 根目录。
命令：py -3 report.py --input input/records-practice.json
预期：输出工作记录汇总。
实际：粘贴完整错误文本，包括最后几行。
最近改动：我把 minutes 字段的值改成了“40分钟”。

请先定位最可能原因，给一个最小排查动作。
不要先重装环境，不要同时改多个文件。
~~~

粘贴前去掉密钥和不宜分享的实际数据。大多数时候，错误文本比一张裁掉上下文的截图更有用。

## 常见错误只分四类

| 症状 | 先看什么 | 最小动作 |
| --- | --- | --- |
| 找不到 python3 / py | 是否安装、命令是否适合系统 | 运行版本命令 |
| 无法打开文件 | 当前目录与完整路径 | 列出目录里的文件 |
| JSON 格式或字段错误 | 逗号、引号、数字类型 | 对照一条正确记录 |
| 输出文件已存在 | 是否重复保存到同一路径 | 换一个新输出名 |

本教程 report.py 会把常见问题转换成中文提示。如果看到了 Python 的 Traceback，先读最后一行的错误类型，再向上找自己文件里的行号；完整文本仍应保留。

## 从错误类型定位哪一层

| 错误 | 常见含义 | 下一步 |
| --- | --- | --- |
| SyntaxError / IndentationError | Python 还没正确解析代码 | 看报错行附近的引号、冒号与缩进 |
| FileNotFoundError | 运行时找不到路径 | 对比当前目录、文件名和扩展名 |
| JSONDecodeError | 文本不能按 JSON 语法解析 | 用编辑器定位行列，查逗号和双引号 |
| KeyError / TypeError | 字段缺失或值类型不符合运算要求 | 打印脱敏的小样本和类型 |
| ModuleNotFoundError | 当前解释器找不到需要的模块 | 核对解释器与依赖文件 |
| PermissionError | 当前进程无法访问目标 | 检查目标目录、文件占用与账号权限 |

“最后一行”帮助分类，堆栈中的调用路径帮助定位是谁触发错误。不要只复制其中一个英文词给 AI，也不要把内部调用库的一行直接当成必须修改的地方。

如果程序卡住，先看它是在等输入、等网络还是持续计算；记录已经输出的最后一步。按 Control+C 终止后保留现场，给网络操作加有限超时，比无限重复运行更容易找原因。处理权限错误时先试个人练习目录，避免用管理员身份掩盖路径问题。

## 什么时候才需要虚拟环境

虚拟环境是某个项目自己的 Python 依赖目录，避免两个项目需要不同版本的库时互相影响。当前练习没有第三方依赖，不需要创建它。

将来项目确实需要额外包时，在项目目录创建 .venv：

~~~sh
python3 -m venv .venv
.venv/bin/python --version
~~~

Windows PowerShell 对应：

~~~powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe --version
~~~

直接使用环境里的 Python 可以避免激活脚本带来的额外问题。安装依赖时同样用这个解释器执行 -m pip，而不是猜当前 pip 属于哪个 Python。

**.venv** 是依赖环境目录；**.env** 通常是存配置的文本文件。名字相近，用途不同；Python 不会默认自动加载任意 .env 文件。

## 动手做

在副本里把 minutes 的数字换成字符串“40分钟”。确认脚本明确拒绝，再改回数字 40。最后重新检查上一课的总数，而不仅是看错误有没有消失。

**完成标准**：能复现错误、说明原因、验证修复后正常样本仍正确。让 AI 修复时要求报告执行了什么，以及哪些检查没做。

<details>
<summary>自测：为什么不一上来就让 AI 重写整个程序？</summary>

重写扩大了变化范围，可能修好一个问题又引入另一个。先定位一个最小失败样本，通常更容易判断修复是否有效。

</details>
