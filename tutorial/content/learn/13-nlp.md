# NLP：从文字任务到 token、词频与向量

**这一课做成什么**：识别会议整理里的不同语言任务，亲手算一次关键词检索得分，再解释为什么模型需要比关键词更丰富的表示。

**NLP（Natural Language Processing，自然语言处理）**研究怎样让计算机分析、转换与生成日常语言。它包括规则、统计方法和神经网络；你已经做过的事实抽取和摘要都属于这个领域。

## 先确定输出，再选择方法

| 任务 | 输入 → 输出 | 检查对象 |
| --- | --- | --- |
| 分类 | 一条反馈 → 故障/建议/表扬 | 类别定义是否清楚，混合反馈如何处理 |
| 抽取 | 会议记录 → 姓名、日期、任务 | 每个字段有没有原文依据 |
| 检索 | 一个问题 → 候选原文位置 | 需要的证据是否被找回 |
| 生成 | 事实表 → 一段周报 | 是否保留事实、不确定性与必要条件 |

“导出很好，但页面打不开”同时含表扬和故障。若规则要求只能选一个类别，先明确是按主要问题选择，还是应该拆成两条；不能把任务定义的不确定性全部归因于模型不聪明。

**实体抽取**找人名、日期等对象；**关系抽取**还要判断“谁负责什么”。抽到“小林”和“报名表”两个词，不意味着小林就是报名表负责人。结构化输出需要把关系和来源一起保留。

## Token 编号还不是语义

**tokenizer（分词器）**按自己的规则把文字切成 token，并映射到词表编号。token 可能对应词、子词、字节片段、空白或标点相关片段。一个汉字不恒等于一个 token，精确计数需用对应模型的分词器。

编号只标识词表条目。假设“报名”为 17、“截止”为 38，38 并不比 17 更重要，也不是语义距离 21。不同模型的编号不能混用。**one-hot（独热表示）**用只有一个位置为 1 的长向量表示类别；它能区分条目，但本身不表达两个不同词的语义关系。

分词长度影响上下文预算与部分接口的计费，计算成本还取决于模型结构、缓存和处理阶段，不能笼统说所有开销都与 token 数严格成正比。进一步读[分词与 Embedding](../guides/tokenization-and-embeddings.md)。

## 词频也是一种有效表示

**词袋表示**统计每个词出现多少次，暂时忽略顺序。**TF-IDF**把当前文档的词频 TF 与该词在全库的稀有程度 IDF 相乘，给有区分度的词更高权重。

这里为了手算，取 TF 为原始出现次数，IDF 为 $\log(N/\operatorname{df}(t))$：N 是文档数，df 是包含这个词的文档数。不同实现会平滑或归一化，应说明具体定义，不混用结果。[Stanford：TF-IDF](https://nlp.stanford.edu/IR-book/html/htmledition/tf-idf-weighting-1.html)

三个已人工切词的短文档：

~~~text
D1 = 报名 截止
D2 = 报名 名额
D3 = 报告 字段
~~~

“报名”出现在 2 篇，IDF 约 0.405；“截止”只在 1 篇，IDF 约 1.099。它的权重更高表示更能区分这三篇文档，不表示事实更可靠。

下面是独立可运行示例，保存为 nlp_words.py，用 python3 nlp_words.py 运行；Windows 使用 py -3。它不需要第三方库，不训练模型：

~~~python
import math
from collections import Counter

docs = ["报名 截止", "报名 名额", "报告 字段"]
tokens = [text.split() for text in docs]
counts = [Counter(words) for words in tokens]
query = "截止"
df = sum(query in words for words in tokens)
idf = math.log(len(docs) / df) if df else 0.0
for index, count in enumerate(counts, 1):
    score = count[query] * idf
    print(f"D{index}: {score:.3f}")
~~~

预期 D1 为 1.099，D2 和 D3 为 0.000。把 query 改成“报名”，前两篇都为 0.405；改成“停止登记”，全部为 0。这个程序按空格切词，没有学会中文分词或同义词。

## 从静态词向量到上下文表示

**embedding（嵌入表示）**用稠密向量表达条目特征，通常通过训练得到。word2vec 的 Skip-gram 用中心词预测附近词，CBOW 用附近词预测中心词；训练目标让经常出现在类似环境里的词学到相关表示，而不是给每一维人工写上“礼貌程度”等标签。[word2vec 原论文](https://arxiv.org/abs/1301.3781)

这种静态词向量中，一个词条通常有固定表示。但“苹果售后”和“苹果很甜”的“苹果”需要不同上下文。BERT 等上下文编码器让一个位置的表示受周围输入影响，后续可用于分类、抽取等任务。[BERT 原论文](https://arxiv.org/abs/1810.04805)

**检索用句向量**还需要把一段文字编码成可比较的表示，并用适合检索的训练与相似度规则。语言模型内部某一层的 token 向量不能不加判断地当作高质量句向量。向量接近也不保证“允许取消”和“不允许取消”含义相同，更不证明答案有事实依据。

关键词能精确找编号，语义表示能缓解改写；两者可以组合。选择依据是实际失败，例如查询“停止登记”漏了“报名截止”，而不是因为一种方法更新就把另一种全部丢掉。

## 动手做与验收

先运行例子，保留三个查询的输出。再让可用 AI 工具处理“打不开页面”“希望能导出”“提醒功能很好”“导出很好，但页面打不开”四条虚构反馈，要求输出类别列表、原句和待确认项。

检查第四条是否按你规定的多标签规则保留两种反馈。若只有“表扬”，先核对任务是否允许多标签，再决定改任务卡还是换方法。

**完成标准**：能说清当前任务要输出标签、字段、候选还是新文本；能手算两个 IDF 数值；能解释为什么 token 编号、静态词向量和上下文表示是不同东西。

<details>
<summary>自测：某文档的“截止”权重最高，是否就能确定它回答了截止时间？</summary>

不能。它可能写“截止时间尚未确定”。词频分数只帮助排序，答案还要读取句子、条件和来源。把检索得分当作事实概率，是把两种检查混在一起。
