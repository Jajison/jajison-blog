# NLP：让电脑处理文字，到底在处理什么

**这一课做成什么**：能分辨文本任务、token 与 embedding 的用途。

**NLP** 是自然语言处理，研究让电脑分析和生成我们日常使用的语言。它不是某一个软件，而是一类任务与方法。

你前面做的会议整理，已经在用 NLP。

## 先认任务，不急着认算法

| 任务 | 例子 | 可以怎样验收 |
| --- | --- | --- |
| 分类 | 把反馈分为故障、建议、表扬 | 抽查类别是否符合定义 |
| 抽取 | 找出负责人、截止日期、金额 | 与原句逐项核对 |
| 检索 | 找到与问题有关的制度条款 | 看相关条款有没有被找到 |
| 生成 | 写摘要、回复或改写 | 检查事实、完整性与可读性 |

同一份报告可能串起多个任务。先抽取事实，再生成摘要，会比把所有要求挤在一句话里更容易检查。

## Token：模型处理文字的小块

模型通常不会直接把整段原文作为一个数字输入，而是先用**分词器 tokenizer**拆成 token，再映射为编号。token 可能是一个词、一个字、字的一部分，甚至空格或标点相关的片段，取决于具体分词器。

不要把“一个汉字等于一个 token”当成通用规则。不同语言、文本内容和模型的计数可能不同。

这影响两个实际问题：能放多少上下文，以及某些 API 的使用量计费。精确计数应使用对应模型或平台的计数工具。

## Embedding：用一组数字表示特征

**Embedding（向量表示）**把文本转换为一组数。经过相应训练后，含义相近的文本在某种相似度计算下往往更接近，因此可以辅助搜索。

“怎么申请年假”和“休假需要什么手续”没有很多相同的字，也可能被语义检索关联起来。向量不是一个保存事实真假的抽屉：接近不代表相同，更不代表内容可信。

同时，金额、产品编号等精确字段往往仍需要关键词或结构化匹配。不能因为使用向量就放弃核对数字。

## 动手做

给 AI 三条虚构反馈：“打不开页面”“希望能导出”“提醒功能很好”，要求分类、引用原句，并为难以分类的情况保留“待确认”。再加一句“导出很好，但页面偶尔打不开”，观察它是否承认包含两种反馈。

**完成标准**：你能先描述自己要做的是分类、抽取、检索还是生成，再选择检查方法。现在不需要学习词向量训练或语法分析算法。

<summary>自测：相似度最高的文档，一定能回答问题吗？</summary>

不一定。它可能只谈同一话题，却没有问题需要的事实。检索得到候选之后，还要检查证据是否充分。
