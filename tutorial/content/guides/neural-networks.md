# 神经网络怎样学习：从一个参数到训练、验证与泛化

**这一课做成什么**：分清程序规则与从数据中学到的参数，理解为什么训练损失下降不等于系统可靠。

## 规则程序与学习系统

普通脚本可以直接规定“status 等于 done 的分钟数相加”。机器学习则适合规则难以完整列举的任务，比如判断一段反馈是抱怨还是建议：准备样本和目标，选一个参数化函数，通过训练调整参数。

监督学习使用输入与目标，例如文本与类别；自监督学习从数据本身构造目标，例如遮住一个词，或用前文预测下一 token；强化学习根据行为与环境反馈优化策略。它们不是简单的“有人管 / 没人管 / 多试几次”，区别在训练信号和优化过程。

## 一个神经元在算什么

常见基本形式是 $h=\sigma(Wx+b)$。$W$ 是权重，$b$ 是偏置，$\sigma$ 是非线性激活。多层只做线性变换仍可以合成一个线性变换；非线性让网络表达更复杂的关系。

ReLU 是 $\max(0,x)$；GELU 是平滑的门控形式；SwiGLU 使用两条投影分支逐元素相乘。它们不是把自然语言规则写进模型，而是提供可训练的函数结构。

参数是训练后保留下来的权重；激活是某次输入经过网络产生的中间值。学习率、层数、批量大小等由训练配置决定的量叫超参数，不能混称为模型已经“学会”的参数。

## 一轮训练的真实顺序

### 先检查一个两层网络的形状

设一次有 B 条数据，每条 2 个特征，隐藏层 3 个单元，最后输出 1 个数。使用“样本按行”的约定：

$$
H=\operatorname{ReLU}(XW_1+b_1),\qquad \hat Y=HW_2+b_2
$$

X 是 $B\times2$，$W_1$ 是 $2\times3$，$b_1$ 有 3 个数；H 是 $B\times3$，$W_2$ 是 $3\times1$，$b_2$ 有 1 个数。参数总数为 $2\times3+3+3\times1+1=13$，与当前 batch 有多少条数据无关。bias 沿 batch 维广播，表示每条样本使用同一组可学习偏置。

输入更多数据会增加激活和计算，不会自动增加这 13 个参数。模型规模与输入规模由此成为不同概念；后面的 LLM 同样需要把参数、上下文长度和 batch 分开计算。

### 开始一次更新

1. 从训练数据取一批样本，称为 batch。
2. 前向传播得到预测。
3. 损失函数比较预测与目标。
4. 反向传播得到参数梯度。
5. 优化器更新参数，然后开始下一批。

一次参数更新通常称为 step；完整遍历一次训练集称为 epoch。梯度累积会让多个微批次合成一次更新，所以 batch、step、epoch 不是固定的一一对应。

下面只演示单参数梯度下降，不是完整神经网络框架。在练习目录新建 `one_step.py`，保存后用 Python 运行：

~~~python
x, target, weight, rate = 2.0, 4.0, 1.0, 0.1
before = (weight * x - target) ** 2
gradient = 2 * x * (weight * x - target)
weight = weight - rate * gradient
after = (weight * x - target) ** 2
print(f"weight={weight:.1f}; loss: {before:.2f} -> {after:.2f}")
~~~

输出应为 `weight=1.8; loss: 4.00 -> 0.16`。真正的网络使用 PyTorch 等成熟框架自动求导，不需要手写每个梯度。学习这个小例子，是为了理解框架到底在执行什么。

## 为什么需要三份数据

训练集用于更新参数；验证集用于选超参数、调流程和早停；测试集用于在决策完成后估计未见样本表现。不断看测试题改模型，会把测试集变成隐形验证集。

拆分不总是随机打散。如果同一个人的相似记录同时进入训练和测试，结果可能过于乐观；预测未来数据时，常需按时间拆分。文本去重、用户隔离、归一化统计只在训练集拟合等，都是防止泄漏的措施。

**过拟合**：训练数据表现很好，新数据差。可能原因包括样本太少、重复、模型过强或调参过度。**欠拟合**：训练和验证都差，可能是模型能力、特征、优化或目标有问题。应看两条曲线和错误样例，不只看最后一个 loss 数字。

## 常用改进如何判断

例如把同一份周报只改日期得到十个副本，再随机分进训练和测试，测试分数可能主要反映记忆模板。先按来源文档或业务主体分组拆分，再做文本预处理。用于标准化的均值方差、特征筛选与词表学习也应在合适的训练范围内拟合，避免提前看见测试信息。

| 手段 | 试图解决什么 | 不能保证什么 |
| --- | --- | --- |
| 更多高质量数据 | 覆盖不足 | 重复和错误数据不自动有益 |
| 正则化、weight decay | 约束复杂度 | 并非越强越好 |
| Dropout | 训练时随机屏蔽部分激活 | 推理通常关闭，不是永久删神经元 |
| 早停 | 防止继续拟合噪声 | 验证集仍需代表任务 |
| 学习率调度、warmup | 改善优化稳定性 | 不能修复标签口径错误 |
| 梯度裁剪 | 限制极端梯度 | 不等于解决所有数值问题 |

Adam/AdamW 会维护梯度相关的状态，因此训练内存通常远大于仅保存模型权重。批量大小、序列长度、精度和激活保存也会影响占用，后续在 [推理与部署](inference-and-deployment.md) 分开计算。

## 指标要符合真实代价

若 100 条记录只有 2 条异常，全部预测正常也有 98% accuracy，却一个异常都抓不到。令 TP 为正确检出的正例、FP 为误报、FN 为漏报：

$$
\mathrm{Precision}=\frac{TP}{TP+FP},\qquad
\mathrm{Recall}=\frac{TP}{TP+FN}
$$

Precision 关心报出来的有多少正确；Recall 关心该找到的找回多少。分母为 0 时需要约定处理方式。阈值影响误报漏报，指标应连同样本分布和具体代价一起讨论。

## 动手做

设 10 个真实异常中抓到 8 个，又把 2 个正常误报。算出 Precision 和 Recall 均为 0.8。再把漏报代价设置为误报的 10 倍，讨论是否应该改变阈值，而不是只追求 accuracy。

**完成标准**：能指出前向、损失、梯度、更新分别是什么；训练、验证、测试各用在哪一步；“分数更高”必须说明哪个数据集和什么指标。
