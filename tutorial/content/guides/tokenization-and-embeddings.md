# 分词与 Embedding：文字如何变成模型能算的数

**这一课做成什么**：解释“文本 → token ID → 向量 → 上下文表示”的链路，并知道向量数据库实际存的是什么。

## Token 不是固定意义的词

英文空格、中文文字、标点、代码缩进、特殊标记都可能影响分词。分词器先按自己的规则切分，再映射到词表里的整数。ID 42 不比 ID 21 “大一倍意义”，编号只是查表索引。

词级分词词表可能很大、遇到新词难处理；字符/字节级覆盖广但序列长；子词方法在词表规模与序列长度之间折中。BPE 常从基础单元出发，依据训练语料中的频繁相邻组合逐步合并；实际分词器还涉及预切分、归一化、字节表示与特殊 token 规则。

下面是**人为教学语料**：`low low lower`。频繁的 l+o、lo+w 可能依次合并。这个例子不声称任何商用模型会得到相同切分。BPE 合并表是分词器训练的产物，推理时不能每遇到一个句子就临时重新学习整张词表。

WordPiece 与 BPE 的训练准则并不完全相同；Unigram 从候选子词集合出发按概率模型选择词表；SentencePiece 是支持多种子词算法的工具，不是与 BPE 完全互斥的某一个算法名称。Byte-level 方法以字节为基础，UTF-8 下一个汉字可能占多个字节，但 token 又可能合并多个字节。

### 手动执行两轮 BPE

把前面的 low low lower 展开：按空格隔开三个词，不跨空格合并，也暂不加词尾标记。初始相邻对 l/o 与 o/w 各出现 3 次，w/e 与 e/r 各出现 1 次。约定同频时先选 l/o，第一轮得到 `lo w`、`lo w`、`lo w e r`；第二轮 lo/w 出现 3 次，合并后得到 `low`、`low`、`low e r`。每轮都在上轮结果上重新统计，不能同时套用已经失效的相邻关系。

推理时使用已经保存的规则顺序进行编码。这里的同频选择和预切分是教学约定；真实工具还须定义特殊符号、未登录字节、归一化与可逆解码，不能把这个小例子当成完整 tokenizer 实现。

## 分词为什么影响使用体验

同一段中文或代码，在不同分词器下 token 数不同。上下文限制、API 用量、生成速度因此都不能单凭字符数精确估算。必须使用所选模型对应的 tokenizer 或供应方的计数结果。

分词器与模型权重是配套关系。换一套 ID 词表再把原权重直接套上，编号对应的表示会错位。特殊 token、聊天模板和角色边界同样影响模型看到的序列。

## 三种“向量”不要混用

| 表示 | 怎样来 | 主要用途 |
| --- | --- | --- |
| Token embedding | 查词嵌入矩阵的某一行 | 进入模型的初始表示 |
| 上下文隐藏状态 | 经过多层网络后得到 | 编码当前位置结合上下文的特征 |
| 文本检索 embedding | 专门模型与 pooling/训练目标产生 | 把查询和文档放到可比较的空间 |

词表大小为 $V$、表示维度为 $d$，embedding 矩阵为 $E\in\mathbb R^{V\times d}$。输入长度 $T$，查表得到 $T\times d$。这里不需要先构造一个巨大的 one-hot 矩阵再做乘法，查表是常见的高效实现。

同一个 token 在不同句子里初始 embedding 可能相同，但网络产生的隐藏状态不同。一个句子的所有 token 取简单平均，也不必然等同于经过对比学习训练的句向量。

## 检索向量怎样学得可比较

对比学习常让相关的查询/文档表示接近，让负例相对远离。模型、训练数据、池化策略、归一化和查询提示前缀共同决定空间的含义。不能把 A 模型生成的查询向量与 B 模型生成的文档向量直接比较，即使维度相同也不意味着坐标系相同。

对非零向量，余弦相似度比较方向。若向量已做单位长度归一化，点积就等于余弦相似度；未归一化时，向量长度会影响点积排名。数据库所配置的距离函数必须与 embedding 模型建议一致。

相似度 0.86 不是 86% 的事实正确概率，也不是跨模型统一阈值。“退款允许”和“退款不允许”可能因为主题相近而很靠近；合同编号、日期和金额仍应精确过滤。

## 传统检索没有过时

用**手工向量**检查距离选择：查询 q=[1,0]，候选 a=[2,0]、b=[10,10]。点积分别是 2 和 10，偏向 b；余弦分别是 1 和约 0.7071，偏向 a。这个算例展示长度怎样改变排名，不代表真实语义向量。先把向量都归一化，再计算点积，排名便与余弦一致。

TF-IDF 用词频和逆文档频率形成稀疏特征；BM25 进一步处理词频饱和与文档长度归一化。向量检索擅长语义相近但文字不同的候选，关键词检索常更擅长编号、专名和精确短语。混合检索的价值是互补，不是把两份不可比的分数随意相加。

ANN（近似最近邻）为了速度允许遗漏部分最相近结果；它不是“近似生成答案”。索引参数影响召回、内存与延迟，应在自己的数据上评估。

## 动手做

向量索引还需要保存文档 ID、片段位置、版本与访问权限。只有向量没有原文，无法给出可核对引用；只按相似度返回未授权片段，也可能泄露内容。完整流程见 [RAG 工程](rag-engineering.md)。

准备四句公开练习文字：“支持七天退款”“不支持退款”“发票申请方式”“订单编号 A-102”。先用肉眼判断查询“能退钱吗”和“A-102”的相关结果，再比较关键词搜索的得失。不要把自己设定的数字画成“真实 embedding 测量”。

使用真实 embedding 服务或本地模型时，记录模型标识、维度、版本、距离函数和是否归一化。资料有隐私时，先确认是否可以传到远端。改模型后通常要重建文档向量索引。

**完成标准**：能说明 token ID 为何不是数值特征，为什么不同模型的向量不能直接混用，以及检索命中后仍需核查哪些事实。

<details>
<summary>自测：token embedding 与 RAG 里的 embedding 是同一层东西吗？</summary>

不是。前者通常是语言模型的输入查表；后者通常是经过特定训练与聚合得到的文本级表示，用来比较查询和文档。二者都叫 embedding，但粒度、训练目标和用途不同。
