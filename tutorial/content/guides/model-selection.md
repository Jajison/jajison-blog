# 模型选型：读懂模型卡，用自己的任务比较

**这一课做成什么**：为“从中文工作记录抽取结构化事实”选择候选方案，明确淘汰条件，并留下别人可以复查的比较记录。这里不提供随发布时间变化的冠军榜。

## 先分清你在选择哪一层

**架构**是模型的计算结构，**权重**是训练得到的参数，**模型家族**是相关版本的命名集合，**产品或 API**是把模型接给用户的服务。base 常指基础模型，instruct/chat 常表示做过指令或对话适配；具体意义仍以发布者说明为准。

同一个家族可能有不同大小、模态、后训练方式和许可证。一个聊天网站支持文件上传，可能是产品先解析文件后把文本送给模型；不能据此断定原始权重直接支持 PDF。

| 要完成的任务 | 可比较的计算路线 | 为什么 |
| --- | --- | --- |
| 固定类别的文本分类 | 编码器加分类头、规则、生成模型 | 输出有限，不一定需要逐 token 生成 |
| 开放式文本生成 | 自回归生成模型、序列到序列模型 | 需要根据输入产生可变长度结果 |
| 大规模资料检索 | 检索专用 embedding、关键词检索 | 需要可比较的表示或索引 |
| 读图表、截图 | 明确支持图像输入的模型与处理器 | 纯文本 tokenizer 无法直接理解像素 |

编码器、解码器和编码器–解码器的结构差别见 [Transformer](../learn/14-transformer.md)。架构只提供能力线索，训练数据、目标、规模与部署实现同样影响结果。检索向量模型、重排模型和聊天模型的输出接口不同，不应互相直接替换。

## 用具体名字理解家族与版本

下面是有明确论文可追溯的历史例子，用来学习阅读模型说明，不构成当前购买或部署推荐：

| 例子 | 阅读时重点看什么 |
| --- | --- |
| [BERT](https://arxiv.org/abs/1810.04805) | 双向上下文表示与下游任务适配；不能直接当聊天产品使用 |
| [T5](https://arxiv.org/abs/1910.10683) | 用统一的文本到文本形式组织不同任务，输入提示与任务格式也是接口的一部分 |
| [Llama 2 / Llama 2-Chat](https://arxiv.org/abs/2307.09288) | 同一发布中区分预训练与面向对话的后训练版本，不能把家族名当完整标识 |
| [Qwen2.5](https://arxiv.org/abs/2412.15115) | 一个家族有多个大小及适配方向，比较时需要具体模型、版本与配置 |

相似的名字可能连接不同数据与训练目标。一个系列更新了视觉模型，不意味着该系列旧的纯文本权重自动获得看图能力；选择时仍回到具体模型卡与接口。参数更多也不自动意味着某个 JSON 抽取任务更合适，下面用实际样例做判断。

## 模型卡是起点，实验是证据

**模型卡**是随模型发布的说明，通常记录用途、训练背景、评估和限制；Hugging Face 模型仓库常用 README 加元数据承载它。模型卡也是作者的自述，需要检查评估条件和自己复现，而不是只摘最高分。[模型卡文档](https://huggingface.co/docs/hub/model-cards)

打开一张模型卡时，边读边填这份记录：

~~~text
候选标识：发布者 / 精确模型名 / revision 或服务版本
用途：从中文记录提取负责人、时间、状态、原文出处
输入接口：文本；最大输入与输出的计算规则
运行要求：tokenizer、聊天模板、精度、依赖、硬件
发布许可：准确链接与版本；待确认的使用条件
已报告评估：数据集、提示格式、是否使用工具
已知限制：中文、长文、拒答、结构化输出等
本地观察：未执行前留空，不填作者排行榜数字
~~~

**revision** 是文件版本标识；**聊天模板**把角色和消息排成模型训练时使用的格式。权重相同但模板、量化版本或截断设置不同，也可能产生不同结果。因此“跑的是同一个名字”还不足以公平比较。

## 开放权重与开源要分别检查

**开放权重**一般说明参数可获得，但不自动意味着训练代码、数据说明、修改与再分发权利都同样开放。OSI 的 Open Source AI Definition 1.0 将使用、研究、修改、分享所需的权限与材料一起考虑；它是一个明确命名的定义，不能仅凭模型能下载就替发布者判定所有权利。[OSI 定义](https://opensource.org/ai/open-source-ai-definition)

选型时记录模型本身、代码、数据、附加组件各自的许可证与版本。授权、隐私、部署地区等条件需要以实际提供方文件和组织要求为准；本课不把任何家族名称等同于“所有用途都许可”。

## 先定淘汰条件，再比较偏好

为这个练习设一组**教学条件**：输入都是可公开的虚构记录，输出必须能解析为 JSON；不得编造金额；负责人或日期缺失时返回 null；日常使用能接受的延迟由你自己测量并填写。它们不是所有业务的通用门槛。

先检查硬条件，例如是否支持所需输入、运行环境是否可用、是否满足数据边界。通过后再比较质量、延迟和成本。不合格的方案不能靠“表达更自然”补回关键事实错误。

准备十个开发样例：三条清晰记录、两条缺字段、两条日期更新或冲突、一条混合语言、一条长文干扰、一条材料没有答案的问题。再留一组没有用于调提示的新样例。对两个候选使用同一资料、字段定义、输出预算与工具配置，保存原始输出和实际返回错误。

| 检查项 | 记录方法 |
| --- | --- |
| 事实 | 姓名、日期、状态逐字段对照原文 |
| 结构 | JSON 能否解析，必需字段与类型是否符合约定 |
| 不确定性 | 缺信息时是否留空，冲突是否被保留 |
| 代价 | 完整任务时间、调用次数、可获得的实际费用 |
| 稳定性 | 同条件重复时是否改变事实、出现超时或拒答 |

不要为了公平而强制两个接口都设置它不支持的参数。记录差异；比较的是可用配置下的完整方案。如果一个候选用了联网搜索，另一个没有，要单列为系统能力差异。

## 算每份合格成果的代价

假设 A 完成 20 次测试，总调用费用 1.20 元，其中 15 份满足全部标准；B 总费用 2 元，有 19 份合格。这只是教学数字，不是任何模型报价：

$$
C_{\text{合格成果}}=\frac{C_{\text{全部尝试}}}{N_{\text{合格}}}
$$

A 为每份 0.08 元，B 约 0.105 元。还要计入重试、检索、人工复核和失败影响。若合格数为 0，不应输出“成本为 0”，而应标记不可用。

延迟也要看分布。平均值可能被少数很慢的请求掩盖；P95 表示按选定统计方法约 95% 的观察值不超过该延迟。小样本的分位数很不稳定，要同时保留样本数、范围和测量方式。首 token 到达很快，也不等于整份成果交付很快。

## 动手：形成一页选择记录

先用一个你已能使用的模型完成五个虚构例子，不需要购买第二个服务。暂时没有可比候选时，先比较同一模型的两个提示版本，并明确实验对象是提示。

交付一张表：版本、样例、原始输出、字段检查、延迟、结果；另写三句话说明“哪个方案在什么任务上合格、为什么、哪些条件还没验证”。价格与服务能力若影响真实决定，应在决定当日重新核查官方说明。

**完成标准**：能把家族宣传、作者评估和自己的观察分开；能解释一个淘汰案例；能给出下一轮应补的样例，而不是只说“这个模型更强”。
