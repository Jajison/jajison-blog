# 把 Codex 用得更顺：读项目、修问题、做重复任务的小工具

**这一篇做成什么**：继续修改自己的待办网页，或让 Codex 为一个重复任务做小工具。使用上的进阶从任务拆分和检查开始。

## 用途一：先读懂已有项目

下载或打开一个项目后，先明确自己是想使用成品、运行源码还是修改它。

~~~text
请读这个目录，用普通语言说明它做什么。
先告诉我：主要入口、输入、结果保存在哪里。
我的目的：在本机用起来。
请区分需要安装的工具、项目依赖与实际运行步骤。
没有读到或无法确认的地方注明。
~~~

要求它按“用户能做什么”解释，再介绍文件。先核对 README 和实际文件，不要让它只按文件名猜。GitHub 项目下载后的基本区别见 [GitHub 从零开始](github-from-zero.md)。

## 用途二：增加一个功能

给待办网页加“只看未完成”，不要同时改配色、账号和同步。

~~~text
增加一个筛选按钮，能显示全部或仅未完成。
当前已有新增、完成、保存和导出，继续保持正常。
筛选只改变显示，不删除记录。
先说明需要改哪些文件，再完成并检查。
~~~

增加之后：勾选一条 → 筛选 → 刷新 → 切回全部 → 导出。导出的三条应仍完整，不能只导出当前画面里显示的两条，除非你明确想要该行为。

## 用途三：修一个可复现的问题

把错误写成“输入什么、点什么、得到什么”。请 Codex 先复现或定位，再修；修完用同一操作验证。

“偶尔丢数据”太宽泛，可以缩为“添加三条，刷新后列表为空；网址为……，浏览器为……”。如果无法复现，让它列出需要补的信息。

查看修改时，可以要求：“用日常语言说明哪个文件改了、为什么、会影响哪个操作。”桌面差异视图或 CLI 的 `/review` 可辅助查问题，具体按当前入口。[官方代码审查说明](https://learn.chatgpt.com/docs/code-review?surface=cli)

## 用途四：把重复操作做成小工具

例如每次手工统计费用，可以让 Codex 做“选择 CSV → 核对字段 → 汇总已确认金额 → 导出结果”的本地工具。先用四条练习费用，确定 250 元的预期，再换自己的允许使用材料。

不要一开始就要求登录、共享、多端同步。只有自己使用时，可以先在本机完成；确实要给其他人用时，再了解部署与账号问题。

## 给项目留下简短说明

在目录里保存一份“使用说明”，包括工具目的、怎样打开、数据保存位置、已完成功能、检查步骤和已知限制。下次打开任务时让 Codex 先读这份说明。

开发项目常用 `AGENTS.md` 保存长期工作约定。本篇只需要几条与当前项目有关的规则：保留原数据、修改后检查主要功能、说明实际验证结果。内容过长或互相矛盾，会增加理解负担。

## 什么时候需要 Skill 或插件

经常重复同一套操作时，可以先保存任务卡；确认它稳定有用后，再看产品提供的 Skill 入口，把步骤与资源封装成可复用方法。插件或连接器适合确实要接外部资料与应用的任务。[Codex 官方 Skills 与 Plugins](https://learn.chatgpt.com/docs/skills-and-plugins?surface=cli)

安装之前看看它处理什么、需要什么资源、是否适合当前任务。工具越多，越需要知道结果来自哪里；不用为了“玩转”而一次装齐。

## 一份清楚的交付记录

~~~text
本次改动：新增未完成筛选。
结果文件：todo.html。
已经检查：三条新增、勾选、筛选切换、刷新保留、完整导出。
尚未检查：其他浏览器与手机实机。
遇到问题怎么恢复：使用修改前备份。
~~~

这份记录可以由 AI 起草，你按实际检查结果修正。运行过一次不能写成所有设备都通过。

**完成标准**：新增功能可用；原有功能仍通过；保留修改前版本；下一次能从项目说明继续。

<details>
<summary>自测：增加筛选后列表少了两条，怎样判断它只是隐藏还是删除了？</summary>

切回全部、刷新并检查导出文件。如果记录仍完整，筛选只是改变显示。只看当前画面不足以判断数据是否保留。
