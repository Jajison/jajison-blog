# 新增文章的编辑模板

新增内容前先判断：它是否帮助目标读者完成一个新的必要动作？如果只是更全面，优先放到延伸阅读。

~~~yaml
title: "编号｜一个读者能理解的问题"
description: "一句话说明完成这课的收益"
lesson: 21
stage: "对应阶段"
duration: 20
prerequisites: [已有文章标识]
outcome: "一个能观察到的结果"
tags: [最多三个相关标签]
~~~

正文顺序：一个真实困惑 → 本课产物 → 最少解释 → 操作与输入 → 正常输出 → 常见失败 → 小练习 → 完成标准 → 一个自测及答案 → 下一步。

主标题下保留可见的“这一课做成什么”一句话，与 outcome 一致，读者无需依赖网站模板才能看到目标。当前主线固定为 20 课；示例编号仅展示字段格式，新增主线课前须同步调整学习路线和校验工具。

## 编辑检查

- 每段只推进一个意思；术语首次出现要解释。
- 以 600–1200 汉字为常见范围，代码与操作必要时可稍长。
- 不把 Windows PowerShell 与 sh 命令混在一个未标注代码块里。
- 每个运行命令都交代目录、依赖、输入输出与停止方式。
- 清楚标识“可运行代码”“伪代码”“示意输出”。
- 比喻结束后交代边界，不从比喻推导技术事实。
- 稳定概念与特定产品行为分开；产品行为附官方来源。
- 不把“AI 自称完成”当成测试证据。
- 不在正文引入与读者无关的仓库维护细节。
