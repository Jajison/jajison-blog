# 定位与内容边界

对外名称：**Jajison · 把 AI 用起来**。核心读者是不懂计算机、希望了解 AI 并改善工作、学习与生活的人。深入首先指使用上的深入：选择工具、准备材料、提需求、修改、纠错、核对结果和保存成果。开发与模型原理仅作按需拓展。

## 读者与组织方式

不要预设读者认识操作系统、芯片、文件扩展名、终端、GitHub 或安装流程。第一次出现这些概念时给具体位置、动作、输入和预期输出；禁止用“很简单”“配置一下环境”跳过步骤。Windows PowerShell 与 macOS/Linux 的命令分别标明，跨平台脚本与 Shell 语法分开解释。

内容以 curriculum.json 为路径配置：12 条路线、52 篇路径文章。前五条主线围绕电脑起步、目的与工具、写作查资料学习、办公文件、Codex 与 WorkBuddy；包括 16 篇新增使用指南。其余路线用 optional 标明，首页默认折叠。首页、侧栏、阅读顺序与计数读取同一配置；禁止用空页面凑篇数。

主线文章必须交代用什么应用、先准备什么、怎样提出任务、第一次结果、具体修改、检查与保存，以及失败时如何反馈。让读者直接打开素材练习，不预设终端、Python 或 API 作为日常使用前提。

## 内容应展开到什么程度

| 主题 | 必须做到 |
| --- | --- |
| 日常 AI 用法 | 适用任务、材料准备、操作与任务卡、修改反馈、结果核对、保存与重复使用；无需代码的练习优先 |
| Codex / WorkBuddy | 普通语言认识工具、选择工作目录、做第一件小事、查看真实文件、具体排错与渐进复用；桌面入口优先 |
| 电脑与运行环境 | 系统和架构、路径、文件格式、安装、解释器、PATH、虚拟环境、权限与可复现排错 |
| 开发与协作 | HTTP 请求响应、Git 工作区/暂存/提交、GitHub 下载/PR、SQL、测试与发布路径 |
| 数学与模型 | 符号/张量形状、点积/softmax/梯度、Transformer 各模块、训练对齐、推理与量化 |
| RAG | 切分、稀疏/稠密检索、混合排名、重排、引用、权限、更新与独立检索指标 |
| Agent | 工具 schema、控制循环、MCP、状态、超时、预算、幂等、恢复与观测 |
| 质量与交付 | 基线、冻结评估集、失败案例、回归、CI、上线检查与回滚 |

深度不靠名词数量。每个专业主题至少说明“解决什么、如何计算、何时成立、怎样失败、如何检查”；数学例子标明假设与单位。纯教学数据、近似估算与真实实验必须区分。

## 示例与证据

使用虚构的工作记录与活动资料串起入门项目；不复制用户私人资料、个人经历或业务数据进公开内容。用户指定知识笔记用于发现主题与理解结构，技术结论再核对官方文档和原始论文，不照搬绝对化经验结论。

Python 主练习使用标准库，可离线运行。HTTP 是真实本地通信，SQLite 是真实数据库操作，检索评价针对实际脚本；受控循环使用确定性策略，不冒充调用真实模型。可选模型实验必须另列安装、下载、硬件、授权、费用和验证范围。

文章里的“预期输出”和维护记录里的“实际通过”是不同证据。未实测 Windows、GPU、外部模型、公开发布，均不能声称已验证。题目不能只背定义；至少让读者预测一次变化、解释一次反例或核算一个数值。
